# Entity Framework Core

## Entities and database providers

Entity Framework Core maps C# entity types and their properties to relational tables and columns. It translates supported LINQ queries into database commands and tracks entities when you plan to update them. Inspect the emitted SQL when query shape or performance matters.

Configure a database provider explicitly. This context uses SQLite, a local database that suits a small exercise. `ToQueryString` lets you inspect a sample translation without creating a database. Use raw SQL where the query needs provider-specific features that your LINQ provider cannot express.

```csharp
using Microsoft.EntityFrameworkCore;

var builder = WebApplication.CreateBuilder(args);
builder.Services.AddDbContext<LibraryDb>(options =>
    options.UseSqlite("Data Source=library.db"));
var app = builder.Build();
app.MapGet("/query", (LibraryDb db) => db.Rooms.Where(room => room.Id > 1).ToQueryString());
app.Run();

sealed class LibraryDb(DbContextOptions<LibraryDb> options) : DbContext(options)
{
    public DbSet<Room> Rooms => Set<Room>();
}
sealed class Room { public int Id { get; set; } public string Name { get; set; } = ""; }
```

## Define and apply migrations

A migration records a schema change from the model snapshot. Generate the initial migration, then add a property and generate a second one. Inspect the generated operations before applying them, especially for renames, data conversions, or removal of columns.

Run this example using the migration commands in the chapter's Notes tab. Keep the migrations and snapshot under source control for a real project. For databases managed by migrations, use the migration workflow from the start. `EnsureCreated` is for disposable databases that do not follow this workflow.

```csharp
using Microsoft.EntityFrameworkCore;

var builder = WebApplication.CreateBuilder(args);
builder.Services.AddDbContext<LibraryDb>(options =>
    options.UseSqlite("Data Source=migrations-library.db"));
var app = builder.Build();
app.MapGet("/rooms", (LibraryDb db, CancellationToken ct) =>
    db.Rooms.AsNoTracking().ToListAsync(ct));
app.Run();

sealed class LibraryDb(DbContextOptions<LibraryDb> options) : DbContext(options)
{
    public DbSet<Room> Rooms => Set<Room>();
}
sealed class Room { public int Id { get; set; } public string Name { get; set; } = ""; }
```

## Insert a record and return its identifier

Call `Add` to mark a new object for insertion, then call `SaveChangesAsync` to persist it. With an integer primary key generated by the database, the saved entity gets the assigned identifier. Bind write requests to a small input type so clients only control the intended fields.

This sample creates a disposable schema at startup and uses a request-scoped context to add each room. POST JSON such as `{"name":"Maps"}` to `/rooms`. The response returns the generated identifier and a named link to the new record. The [validation chapter](#12_ASP.NET_Core/07_Minimal_API_Binding_and_Validation/concepts/automatic-minimal-api-validation) explains how to validate request models.

```csharp
using Microsoft.EntityFrameworkCore;

var builder = WebApplication.CreateBuilder(args);
builder.Services.AddDbContext<LibraryDb>(o => o.UseSqlite("Data Source=reading-demo.db"));
var app = builder.Build();
await using (var scope = app.Services.CreateAsyncScope())
    await scope.ServiceProvider.GetRequiredService<LibraryDb>().Database.EnsureCreatedAsync();

app.MapGet("/rooms/{id:int}", async (int id, LibraryDb db, CancellationToken ct) =>
    await db.Rooms.FindAsync([id], ct) is Room room ? Results.Ok(room) : Results.NotFound())
    .WithName("ReadRoom");
app.MapPost("/rooms", async (RoomInput input, LibraryDb db, CancellationToken ct) =>
{
    var room = new Room { Name = input.Name };
    db.Rooms.Add(room);
    await db.SaveChangesAsync(ct);
    return TypedResults.CreatedAtRoute(room, "ReadRoom", new { id = room.Id });
});
app.Run();

record RoomInput(string Name);
sealed class LibraryDb(DbContextOptions<LibraryDb> options) : DbContext(options)
{
    public DbSet<Room> Rooms => Set<Room>();
}
sealed class Room { public int Id { get; set; } public string Name { get; set; } = ""; }
```

## Read and project records

Build a LINQ query to filter, order, and project rows before materializing the results. A projection that selects just the fields an endpoint needs cuts down the amount of data read. For read-only entity results, `AsNoTracking` avoids creating tracking entries.

Run this example in the same project after inserting rooms with the [insert example](#12_ASP.NET_Core/12_Entity_Framework_Core/concepts/insert-a-record-and-return-its-identifier). The list uses a stable order and a bounded result set. The detail endpoint uses `FindAsync` to look up a primary key and returns 404 if the record is absent.

```csharp
using Microsoft.EntityFrameworkCore;

var builder = WebApplication.CreateBuilder(args);
builder.Services.AddDbContext<LibraryDb>(o => o.UseSqlite("Data Source=reading-demo.db"));
var app = builder.Build();
app.MapGet("/rooms", (LibraryDb db, CancellationToken ct) =>
    db.Rooms.OrderBy(room => room.Id).Take(20)
        .Select(room => new { room.Id, room.Name }).ToListAsync(ct));
app.MapGet("/rooms/{id:int}", async (int id, LibraryDb db, CancellationToken ct) =>
    await db.Rooms.FindAsync([id], ct) is Room room ? Results.Ok(room) : Results.NotFound());
app.Run();

sealed class LibraryDb(DbContextOptions<LibraryDb> options) : DbContext(options)
{
    public DbSet<Room> Rooms => Set<Room>();
}
sealed class Room { public int Id { get; set; } public string Name { get; set; } = ""; }
```

## Update a tracked entity

A context tracks the entities it loads by default. For an update, load the row, copy just the allowed fields from the input, and call `SaveChangesAsync`. EF detects the modified properties and writes changes. With a concurrency token configured, it can also detect whether another writer changed the row in the meantime.

Run this app with the database created by the [insert example](#12_ASP.NET_Core/12_Entity_Framework_Core/concepts/insert-a-record-and-return-its-identifier). Use the returned identifier and PUT a new name. A missing row yields 404, and a successful edit yields 204. Switch to the [read example](#12_ASP.NET_Core/12_Entity_Framework_Core/concepts/read-and-project-records) to check the saved value.

```csharp
using Microsoft.EntityFrameworkCore;

var builder = WebApplication.CreateBuilder(args);
builder.Services.AddDbContext<LibraryDb>(o => o.UseSqlite("Data Source=reading-demo.db"));
var app = builder.Build();
app.MapPut("/rooms/{id:int}", async (int id, RoomInput input,
    LibraryDb db, CancellationToken ct) =>
{
    var room = await db.Rooms.FindAsync([id], ct);
    if (room is null)
        return Results.NotFound();

    room.Name = input.Name;
    await db.SaveChangesAsync(ct);
    return Results.NoContent();
});
app.Run();

record RoomInput(string Name);
sealed class LibraryDb(DbContextOptions<LibraryDb> options) : DbContext(options)
{
    public DbSet<Room> Rooms => Set<Room>();
}
sealed class Room { public int Id { get; set; } public string Name { get; set; } = ""; }
```

## Database configuration and production migrations

Supply connections through [application configuration](#12_ASP.NET_Core/10_Application_Configuration/concepts/default-sources-and-hosting-environments) and keep credentials outside source control. A `DbContext` represents a unit of work. Keep it scoped and await each operation before using it again; a context does not support concurrent operations.

For production, apply reviewed SQL or a migration bundle as a deployment step with a migration identity. The request-serving process can then run with narrower permissions. This example reads a configured connection string and can report whether it can connect. A successful connection alone does not prove the expected schema is installed.

```csharp
using Microsoft.EntityFrameworkCore;

var builder = WebApplication.CreateBuilder(args);
var connection = builder.Configuration.GetConnectionString("Library")
    ?? "Data Source=migrations-library.db";
builder.Services.AddDbContext<LibraryDb>(options => options.UseSqlite(connection));
var app = builder.Build();
app.MapGet("/database-ready", async (LibraryDb db, CancellationToken ct) =>
    await db.Database.CanConnectAsync(ct) ? Results.Ok() : Results.StatusCode(503));
app.Run();

sealed class LibraryDb(DbContextOptions<LibraryDb> options) : DbContext(options);
```
