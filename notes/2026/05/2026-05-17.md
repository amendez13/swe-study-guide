## Study Site Cache And Deploy Fix

### Implementation
- Verified the live VPS Postgres topic source file under `content/03_Postgres/01_Relational_Model_Foundations/concepts.md` was correct, so the bad UI state was not caused by incorrect course content.
- Confirmed the live `site/app.js` on the VPS already contained the earlier async tab-loading guard (`activeTabRequestToken` and `bar.onclick`), which ruled out a missing frontend branch deploy as the primary cause.
- Added explicit `do_HEAD()` handling in `serve.py` so operational checks hit the same routing path as `GET`.
- Refactored `serve.py` response handling through `_send_ok(...)` and added `Cache-Control: no-store`, `Pragma: no-cache`, and `Expires: 0` headers for:
  - `/`
  - site assets such as `/app.js` and `/style.css`
  - `/api/content`
  - `/health`
  - `/content/...` study material responses
- Added targeted tests in `tests/test_serve.py` covering the new no-cache response headers, skipped response bodies for `HEAD`, CORS handling for content responses, and the existing path-safety and health helpers.
- Identified a deployment bug in `automation/infra/hetzner/swe_study_guide_setup.yml`: repository updates did not notify the systemd restart handler, and the playbook verified health before any pending handler ran.
- Updated the automation playbook so git and pip changes notify `Restart swe-study-guide`, and added `meta: flush_handlers` before service verification.
